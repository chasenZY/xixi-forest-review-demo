    过去 · 人工流转

    01 会员提交申请填写并上报个人信息。
    02 客服下载 DOC逐项查找身份证、手机号、微信号。
    03 人工查询黑名单查库、比对、判断并记录原因。
    04 客服初筛基本问题客服检查四项入会基本问题；任一为否则不通过，并向申请人说明原因；全部为是才转交理事会。
    05 文档转发理事群理事下载文档，阅读后在群里回复。
    06 人工收集判断客服识别人名、查重复与改票，统计通过／不通过／待定。
    07 汇总并联系人工判断结束时机，整理结论，联系申请人。

    优化后 · 分工与自动化

    标注为正式系统实现后的能力；当前 Demo 仅本地模拟。全自动以资料、名单、规则和渠道已配置为前提。

    机器全自动 · 结构化表单01 接收申请与归档表单提交后自动入库、校验必填项、保存原始答案。历史 DOC 提取可自动处理，但异常格式、字段识别及缺失项需人工复核。
    机器全自动 · 规则匹配02 黑名单过滤与归因按标准化身份证、手机号、微信号精确匹配，引用已有名单原因和来源，命中即拦截；未命中进入下一步。名单维护、误报申诉、来源真实性由人工处理；库不可用则暂停流转。
    机器全自动 · 明确规则03 基本问题审批与归因四项全为是则通过；任一为否则归因为“基础问题未通过”，列出具体项；未填则待补充。不再由客服逐份初筛。
    机器全自动 · 模板生成04 生成审核卡片与链接用固定模板展示原始资料、初筛结果、截止时间，自动生成审核链接。可选 AI 摘要属于辅助内容，需复核；不让摘要替代申请原文。
    渠道待核实 · 条件满足可自动05 发送审核提醒现有普通微信群先由客服转发。公众号是否能按理事标签群发、自动发送及发送频率待后台核实；若满足则由机器按配置推送。企业微信内部群可另行评估官方 Webhook。公众号回调不等于向普通微信群发送消息。
    机器全自动 · 绑定后鉴权06 识别理事并校验权限具备公众号网页授权权限时识别 OpenID，匹配理事白名单；否则独立账号登录。首次身份绑定和理事名单维护由管理员确认。
    人工决策 · 理事07 阅读资料并投票每名理事自行判断通过、不通过或待定。机器保存投票、记录改票、一人一票校验；不代替理事作入会判断。
    机器全自动 · 规则结算08 截止结算与汇总24 小时到期，或有效参与人数超过全体理事 2/3，自动停止收票、比较通过与不通过票、冻结结果并生成逐人记录。平票、零票按待跟进规则流转。
    人工处理 · 客服09 处理例外并联系申请人机器生成汇总和联系草稿；客服处理争议、平票、缺失资料并联系申请人。自动结果通知需另核查消息渠道和模板权限，不能视作已完成人工联系。

    判断依据与未决规则

    机器全自动环节：结构化归档、黑名单精确匹配与已有原因引用、基本问题规则审批、模板卡片及链接生成、绑定后的权限校验、收票去重、截止结算和汇总。通知发送能否全自动取决于渠道权限。AI 仅辅助摘要和文字草稿，人工复核；理事决策、名单及身份维护、客服沟通仍由人工负责。 已确认：参与表决人数超过全体理事的 2/3 即结束，再比较通过与不通过票。 暂定：待定／跳过不算有效参与；截止前可改票，每人只保留一张当前票；平票或零有效票交客服跟进；到期按有效票多数形成建议结论，无最低参与门槛。以上暂定规则需上线前确认。 发起时固定理事名单及人数；黑名单命中、基础问题未通过或未填齐时，均不向理事群推送会员资料、不发起投票。库不可用时显示“检测失败待重试”，不能当作未命中。

    DELIVERY & IDENTITY / 推送与鉴权

    先低成本跑通，再接入微信。

    普通微信群里的“群成员身份”，不能直接由一个 HTML 页面读取。分享链接是入口，不是投票权限。

    现有资源 · 待核实

    公众号方案讨论与核实清单

    协会已有微信公众号，优先核查复用条件。订阅号能发消息、能否自动通知指定理事、能否识别网页访问者，是三个独立问题；目前尚未取得后台权限信息。

    • 账号信息：确认订阅号／服务号、主体类型、认证状态与有效期、管理员及开发权限、已有服务商或系统接入。
    • 网页鉴权：在接口权限中核查“网页授权获取用户基本信息”及 snsapi_base 是否可用；确认网页授权域名能配置并完成校验。有权限则后端换取 OpenID；无权限则采用独立账号，不因“能群发”而假定“能鉴权”。
    • 通知对象与频率：确认能否按理事标签群发、理事是否已关注并正确打标、每日实际剩余额度，以及与原有内容推送是否冲突；讨论每日汇总提醒是否满足 24 小时审核节奏。
    • 自动发送能力：分别核查后台手动群发与 API 群发权限、定时能力、可发送内容及审核入口链接方式；如需逐申请实时通知，另核查模板／订阅通知／客服消息的权限、模板、授权和时效条件，不承诺任意主动通知。
    • 服务器回调／Webhook：核查服务器 URL、Token、加解密配置及现有系统是否占用；用于接收微信支持的消息和事件。它不是普通微信群的发送接口，不能单靠回调自动向理事微信群推送。
    • 理事身份绑定：管理员确认 OpenID 与理事本人对应；后续自动白名单鉴权。需确认名单维护人、解绑办法及详细票数的可见范围。
    • 费用与部署：确认可复用的 HTTPS 域名、后端和数据库；核查认证续期、云资源、服务商费用及额度。先只确认权限，不提供或重置 AppSecret。

    核实后的选择：有网页授权则优先公众号鉴权；没有则独立账号兜底。通知按真实权限选择公众号提醒或人工转发；如必须自动发群，则另评估企业微信内部群。当前没有真实接入。

    A / 普通微信群＋独立理事账号

    客服把系统生成的简要通知和审核链接发进现有群。理事首次使用独立账号及随机初始口令登录，后续使用服务器会话记住登录。

    • 无需公众号与短信，不新增消息接口费；利用现有服务器可减少新增开支，部署、维护成本另计。
    • 理事账号由管理员预先创建、单独交付凭据，不能靠选择名字或输入手机号证明身份。
    • 不足：首次要登录；普通微信群转发仍由客服完成。
    已有公众号时优先评估

    B / 群链接＋公众号网页授权

    在微信内打开审核链接 → 网页授权 → 后端用 code 换取 OpenID → 检查理事白名单 → 进入审批页。

    • 第一次绑定时，由管理员确认账号与理事本人对应。OpenID 只能证明微信账号身份，不能自动证明理事资格。
    • 需核查现有公众号是否具备网页授权权限，并配置回调域名；密钥、令牌保存在后端。
    • 公众号通知面向用户，不是直接给任意普通微信群发消息；模板／订阅消息需满足实际接口、模板和授权条件。
    • 如现有账号权限齐备，通常可不新增登录接口采购；新账号认证、域名及托管可能有费用，不能承诺全程免费。

    C / 企业微信内部群＋官方机器人／应用

    若愿意把理事加入企业微信内部组织，可评估群机器人发审核链接；通过自建应用的网页授权识别成员 UserID，再映射理事权限。

    • 机器人发送入口与网页身份识别是两件事；Webhook 不会告诉网页是谁点击。

    • 可以优先评估基础功能，无需另购第三方机器人；认证、服务器和域名等条件仍需核查。

    免费部署的边界

    本地 HTML Demo：免费，可离线演示；没有多人同步和真实鉴权。 小规模试用：可评估有免费额度的 Workers＋D1，账号登录不依赖公众号；免费额度不等于永久免费，且中国大陆和微信内的访问稳定性要实测。 正式业务：优先复用协会已有国内服务器和 HTTPS 域名，按实际资源及平台条件核算费用。AI 摘要可先用固定模板或人工确认，避免把模型接口费变成试运行前置条件。

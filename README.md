# 熙熙森林会员审核 Demo

移动端优先的独立静态网页，演示黑名单过滤、四项基本问题审批、理事限时表决、新旧流程对比及公众号方案讨论。

公开版本使用匿名改写示例，不含真实会员原始文档。仅用于讨论和演示：身份、名单和票数均为模拟，不发送消息，不接入真实审批或微信鉴权。

投票数据只保存在各自浏览器，不能跨设备同步；基本问题通过时默认收起，可手动展开。

## 本地运行

直接用浏览器打开 index.html，无构建步骤或外部依赖。

## 发布

GitHub Pages 从 main 分支根目录发布 index.html。请勿在本仓库提交真实申请资料、黑名单或微信密钥。

更多设计见 [方案说明](方案说明.md)。

## 资料卡表决工作台

/application-review/ 已恢复完整交互流程：从零票开始，每个模拟理事提交通过、不通过、待定；可修改当前票并保留修改历史；24 小时或有效参与超过 2/3 后冻结结果，生成逐人表决和规则快照归档，支持 JSON 导出。基本问题通过后默认折叠。会员编号于审核通过后分配，待审页面不展示会员编号。

当前 GitHub Pages 仍为静态交互演示，保存位置为各自浏览器 localStorage，不是共享数据库，也未绑定微信身份。演示默认 9 个模拟席位，不代表正式理事人数；真实黑名单核验、理事名单和后端部署待确认。页面明确标注本机演示，不得作为正式群收票系统。后续正式实现需后端认证、数据库唯一约束、事务计票、服务端定时截止及长期归档；保持前端布局与交互一致。

## 已确认的表决通过后办理流程

完整顺序：会员提交 → 黑名单过滤与归因 → 客服基本问题初筛（优化后规则自动审批） → 理事会表决 → 确认缴费情况 → 会员信息归档 → 赋予会员编号并拉群。

表决通过不等于入会办理完成。未缴费或到账尚未确认时，保持“表决通过、待确认缴费”；缴费确认后才可建立会员档案，之后赋予编号并确认拉群。未通过及待客服处理者不进入该后续链路。

“表决留档”是冻结票数、意见及历史的审计记录，表决结束即可生成；“会员信息归档”是缴费确认后建立正式会员档案，二者不能混同。原型全部为本机模拟，不实际收款、不分配正式编号、不真实拉群。演示编号必须以 DEMO- 开头。

待二次确认补充：会费标准与周期、缴费核验负责人及凭证要求、未缴费／逾期处理、会员档案字段及权限、编号生成规则及负责人、拉群负责人和完成确认方式。理事名单与人数、服务器与数据库环境仍待协会最终确认。

## 申请表完整还原及下载

HTML 按原表逐项展示字段，补回完整养宠／救助概况、加入理由、帮助诉求、意见建议、四项基本问题原文、原表空白审批栏状态、附注与会员申请办法。姓名和昵称部分脱敏，身份证、电话、出生、微信、住址及单位值隐藏；不将缺失的原始审批栏误作通过。

经用户明确选择，公网仅提供保留原排版的 membership-application-redacted.docx（原申请表脱敏版），完整未脱敏原件后续鉴权下载。原始 DOCX 未上传公网。已用 Word 导出并检查两页，隐藏字段及文字排版正常；检查了 DOCX 各 XML 部件，移除个人元数据，附件中无真实姓名、电话、身份证、微信、住址与单位。原表的缴费／审核顺序按原文保留，并在 HTML 标注其与本次确认的新流程的差异。
